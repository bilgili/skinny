# Recording adapter: live bindings

## Why

`recording_compute.py` is the third GPU adapter (change `gpu-backend-adapter`).
It records allocations, bindings, and dispatches with no device, so dispatch
order and binding coverage become hostless assertions. `Recorder.
missing_bindings()` is its headline: it names every shader global a dispatch
left unbound. An unbound global on Metal is a silent wrong value, not a crash,
so catching it before the GPU is worth a lot.

Today it catches nothing real. Every test drives it by hand:

```python
pipe.reflect_globals({"outputBuffer", "sceneBuffer", "envMap"})   # hand-written
pipe.dispatch(8, 8, binds={"outputBuffer": buf})                  # hand-written
```

The test author writes **both** sides. The assertion is that two hand-written
sets differ in the way the same author expected. No shader is parsed and no host
bind path runs, so a pass that genuinely forgets a binding is invisible.

This matters for every future pass. The next compute pass added to the tree
(the `denoise-pipeline` auxiliary and display passes are the imminent example)
will lean on hostless binding coverage — and against today's recorder that
coverage is a tautology. A pass that declares several output images plus the
bindless pool, or reads the HUD and gizmo buffers, is exactly the shape where a
forgotten Metal bind reads as black rather than as a failure. This change scopes
to the **megakernel** today; a new pass registers once and inherits the gate.

The same defect class already has form here: 3 of the 7 codex defects on
`gpu-backend-adapter` were gates asserting less than their docstring claimed.

## What Changes

- **Declared globals come from the compiler.** A pass's global set is the Slang
  compiler's reflection — `slangc -target metal -reflection-json` over the pass,
  emitted offline into a checked-in golden — instead of being handed to
  `reflect_globals()` by the test. (An earlier design parsed the `.slang` sources
  by hand; that was rejected — a line parser cannot separate a file-scope
  resource global from a resource-typed function parameter without scope
  tracking. See the design's D1.) The hand-written form stays for unit-testing
  the recorder itself, but a real pass SHALL NOT use it.
- **Bind maps come from the host path.** The recorder observes the bind dict the
  renderer actually builds for a pass, so the recorded coverage describes
  production code rather than the test's idea of it.
- **A pass registry.** Each recordable pass declares its entry module, entry
  point, and how to obtain its bind map, so a new pass is registered once and
  gains coverage automatically rather than needing a bespoke test.
- **A coverage gate over every registered pass.** One hostless test asserts that
  every registered pass binds every global its shader declares. Adding a pass
  without registering it fails a meta-test, the same shape as the parity
  matrix's integrator-coverage check.
- **A negative control.** A deliberately unbound global must fail the gate. A
  coverage test that cannot fail is the defect this change exists to remove, so
  the suite proves it fails.

## Capabilities

### New Capabilities

- `recording-pass-coverage`: a pass's declared shader globals from the compiler's
  reflection (a checked-in golden), observing the host's real bind map, the
  registry of recordable passes, and the coverage gate plus its negative control.

### Modified Capabilities

- `gpu-backend-adapter`: the recording adapter gains a compiler-reflection path
  (an offline golden), and the declared-surface rules cover it.

## Impact

**Modified.** `src/skinny/recording_compute.py` (registry + device-free bind
map), `tests/test_gpu_backend.py` (the hand-driven scenarios stay as recorder
unit tests, relabelled as such).

**New.** `tests/fixtures/gen_recording_pass_globals.py` + the checked-in golden.

**New.** `tests/test_recording_pass_coverage.py` — the gate, the meta-test, and
the negative control.

**Scope.** Megakernel only. When `denoise-pipeline` lands its auxiliary and
display passes, each registers here in one line and inherits the gate — their
binding-coverage tasks reduce to that registration rather than asserting nothing.

**Risk.** The declared globals come from the compiler's own reflection, not a
hand parser, so the whole class of parser under-reports is gone: the golden is
generated by `slangc -reflection-json`, cross-checked against the GPU resource
inventory, and re-verified by a device-permitted freshness test.

**Out of scope.** Driving a whole `Renderer` frame against a `RecordingContext`.
That is a much larger change and is not needed: a pass's bind map is obtainable
without constructing a renderer.
